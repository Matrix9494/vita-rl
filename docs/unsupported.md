# Unsupported and Partial DefendPeace Coverage

This file tracks known gaps against the DefendPeace reference implementation.
It is intentionally conservative: a feature stays listed until there is direct
engine support and regression coverage.

## Rule Variants

- AW1, AW2, AW3, AW4, DoR, Kaiju Wars, and non-AWBW rule variants are not
  modeled as separate selectable rulesets.
- The current target is the AWBW-style subset under the `defendpeace_awbw`
  ruleset.
- Experiment configs can restrict the allowed unit pool for production/rule
  spawns, but broader rule toggles and per-player variants are not modeled yet.

## Combat

- Full DefendPeace `StrikeParams` parity is incomplete.
- Several core integer-damage cases are covered, including terrain defense,
  low-HP attackers, counters, indirect fire, best-weapon selection, and air
  defenders ignoring terrain defense.
- Remaining gaps include exact modifier ordering for all CO powers, all edge
  cases around negative luck, and broader Java-derived fixture coverage.

## Commanders

- The implemented AWBW CO roster is a first-pass behavior model, not exact
  event parity for every CO.
- Exact CO power/super-power event parity remains incomplete for meteor
  tie-breaks, spawn/stun edge cases, multi-power interactions, and some counter
  modifiers.
- Tag powers, team bonuses, Dual Strike rules, and full tag-mode parity are not
  implemented.

## Weather

- `clear`, `rain`, and `snow` are implemented with movement/vision effects,
  temporary duration/restoration, and serialization.
- Full DefendPeace forecast queues are not implemented.
- Additional weather variants such as sand/smoke/sirocco/sleet are not modeled.
- CO-specific weather immunity beyond the current Olaf/Drake movement hooks is
  incomplete.

## Fog of War

- Basic visibility, drive-by vision memory, hidden Sub/Stealth reveal, and
  forest/reef cover are implemented.
- Exact DefendPeace fog-view lifecycle, broader fixture parity, and rare cover
  or hidden-state edge cases remain incomplete.
- Temporary fog generated by weather variants is not modeled.

## Movement and Transports

- Path validation, occupancy blocking, weather movement costs, and path-based
  fuel use are implemented for the current movement tables.
- Full DefendPeace movement parity for every movement type and special terrain
  edge case remains incomplete.
- Carrier cargo launch is implemented as a separate engine action, but
  DefendPeace's exact composed "launch plus cargo action" flow is not fully
  mirrored.

## Maps and Terrain

- The DefendPeace text map parser supports common fixed-width maps, several
  `res/map/**/*.map` fixture directories, and unit-name variants such as
  `ANTI-AIR`.
- All current checkout `res/map/**/*.map` files have parse/reset smoke coverage.
- Special terrain behavior on those maps is not exhaustively simulated.
- Terrain destruction, teleports, labs, towers, and non-core special terrain
  behavior are not fully modeled.

## Environment API

- PettingZoo raw and wrapped AEC API tests pass when optional dependencies are
  available.
- `parallel_env()` is implemented through PettingZoo's turn-based AEC-to-parallel
  conversion and passes the official parallel API test.
- `max_turns` produces truncation rather than victory termination.
- Observations are intentionally simple board planes and do not yet mirror a
  final training-optimized representation.
- The parallel environment depends on PettingZoo being installed.
